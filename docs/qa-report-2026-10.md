## 本轮发现并已修复

### 1. E2E 与 UI 改变脱节（P1，CI 会红）

我把「↓ 导出 PDF」入口合并成「预览并导出」、把导入主按钮文案改成动态的「仍要导入」后，两条 E2E 直接失败：

```
waiting for getByRole('button', { name: '↓ 导出 PDF' })
waiting for getByRole('button', { name: '导入并开始编辑' })
```

- 测试侧：改为点「预览并导出」
- 产品侧：主按钮文案改回固定的「导入并开始编辑」，未核对数量改成旁边的提示文案
  （动态主按钮会破坏肌肉记忆，也让自动化不稳定，这条是设计上的退步）

### 2. 导入后的简历标题是文件名（P2）

导入后标题变成 `Agent应用开发简历-含ResumeStudio-脱敏版`，在列表里几乎无法辨认。改为 `姓名 - 目标职位`，识别不到才退回文件名：

```
导入前：Agent应用开发简历-含ResumeStudio-脱敏版
导入后：吴** - Agent 应用开发工程师 / AI 应用后端
```

### 3. 无选区时 AI 改写会覆盖整段描述（P2）

原文实现是「没选中 → `getText()` 取全文 → 替换全文」。实测：描述框里有两段，光标在第二段，点改写会把第一段也一起换掉。改为只替换**光标所在段落**。

验证：改写前 2 个段落，改写后 4 个段落（第一段保留，第二段被替换成 3 条），第一段文本完整未动。

### 4. 撤销可用性（回归确认，非缺陷）

同样的场景下按 Ctrl+Z，内容完整回到改写前。`insertContentAt` 单事务的方案有效。

## 已知非缺陷（QA 过程中排除）

- 首页卡片数显示 4 = 3 份简历 + 1 张「创建新简历」占位卡（`.document-card` 共用类名，脚本计数误判）
- JD 匹配给 40 分：测试用的是几乎空的简历，分数偏低符合预期
- 导入脱敏简历时提示「手机号/邮箱是脱敏格式」：这是设计内的提示

## 建议的下一步

1. 导入时把 `targetRole` 从识别到的「目标职位」写入，并让 JD 匹配优先读取它
2. 首页删除改成软删除 + 撤销 toast，与模块删除对齐
3. 编辑器改成三栏独立滚动（大纲/预览/属性各滚各的），长简历才不会丢上下文
4. 导出前用真实 Chromium 渲染一次做溢出校验，替换 DOM 测量
