# 代码与产品评审（2026-10）

> 触发原因：导入 `Agent应用开发简历-含ResumeStudio-脱敏版.pdf` 后解析结果不可用（姓名变成「电话」、
> 手机号/邮箱丢失、所有内容挤进「教育经历」）。下面先记导入链路的根因与修复，再记整体迭代建议。

## 一、导入链路：三个根因（已修）

| #   | 现象                                   | 根因                                                                                                                                                       | 处理                                                                      |
| --- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1   | 模块标题全部识别不到，只剩「教育经历」 | 子集化字体把汉字映射到**康熙部首区**：`⼈`(U+2F08)、`⼼`(U+2F3C)、`⼯`(U+2F2F)；其中 U+2E80–U+2EFF 段（`⻄`、`⻋`、`⻝`）**NFKC 无映射**，归一化后原样返回 | 只对部首区做 NFKC，另补 10 个无映射字符的对照表（`RADICAL_FALLBACK`）     |
| 2   | 即使还原了字符也匹配不上标题           | PDF 提取时同一行被 `join(' ')`，汉字之间插了空格：`个 ⼈ 简介`                                                                                             | 新增 CJK 间隙合并；仅合并汉字之间，保留中英之间的空格                     |
| 3   | 姓名 = 「电话」，手机号/邮箱为空       | 脱敏写法 `177****8476`、`****@163.com` 不匹配原来只认纯数字/标准邮箱的正则；随后「电话：…」这行被当成姓名行                                                | 正则兼容 `*` 占位；姓名改为「排除联系方式标签 + 从行尾往前找 2-4 字片段」 |

附带修掉的两个问题：

- 日期区间只认「年.月」格式，`2024 - 至今` 切不开条目；且 `至今` 里的「至」被当成区间分隔符，产出 `2023.07--今`。
- PDF 折行把句子切断（`…问答优秀率从` / `68.0% 提升到 89.3%。`），现在会按标点/标签/条目头判定后重新拼接。

## 二、后端

### P0

1. **`isResumeDocument` 只校验 3 个字段**（`id`/`profile`/`sections`），任意 JSON 都能进渲染器。
   渲染器里再抛错就是 500。建议引入 `zod` 做完整 schema 校验，错误按字段返回。
2. **提取层才是空格问题的根源**：`pdfTextExtractor` 把同一行的 `item.str` 直接 `join(' ')`。
   应改为按 `item.width`/`transform` 判断间距，或用 `item.hasEOL` 决定是否折行，
   中文之间不插空格。当前解析器的归一化是兜底，不是最优解。
3. **导出接口无体积上限/超时**：`POST /api/export/pdf` 拿到的 JSON 直接进 Chromium 渲染。
   建议给 Fastify 配 `bodyLimit`，并在导出前限制模块/条目数量。

### P1

4. **AI 改写没有流式输出**：现在 `qwen3-8b` 单次 3–4 s，长段落会等十几秒，前端只有一个「改写中…」。
   项目本身已经在用 SSE 思路（README 里写了 SSE 流式事件），这里应改为 `stream: true` + 增量渲染。
5. **AI 结果直接 `setContent`**，会清空 Tiptap 的撤销栈——用户误点就没法 Ctrl+Z 回退。
   应改为一次事务插入，或先存快照再替换。
6. **本地服务缺少来源校验**：绑定 `127.0.0.1` 已挡住外网，但浏览器里任何网页都能打
   `http://127.0.0.1:4173`（DNS rebinding / 恶意页面）。建议校验 `Origin`/`Host`，非白名单直接 403。

## 三、前端

1. **`src/app/styles.css` 单文件 1316 行**，全部是全局类名（`.rich-editor__toolbar` 这类 BEM 还算克制，
   但已经覆盖首页/编辑器/预览/导入确认四个页面）。建议按 feature 拆分到组件 `scoped` 样式，
   共享的只留 token（颜色/字号/间距变量）。
2. **`importParser.ts` 498 行**，一个文件里塞了归一化、分节、条目、profile、警告五件事。
   建议拆成 `normalize.ts` / `sections.ts` / `profile.ts`，`parseResumeText` 只做编排——
   这次修 bug 时已经能感觉到：改归一化要通读整个文件。
3. **组件直接调 API**（`RichTextEditor` → `localResumeApi`）。跨层调用本身可接受，
   但把「AI 改写」放进 Pinia store 的 action 里，能顺带拿到统一的 loading/error 状态和可测试性。
4. **IndexedDB 无迁移机制**：`schemaVersion: 1` 只是数据字段，存储层没有版本升级路径。
   一旦改字段，老用户数据要么读到 undefined，要么整库清空。建议加 `onupgradeneeded` 迁移表。

## 四、产品

1. **导入体验的关键缺口是「可校正」而不是「更聪明」**。导入确认页（`ImportReviewView`）已经有了，
   但缺少：原文/结果并排高亮、单条「重新解析这个模块」、模块拖拽合并。启发式解析永远有误差，
   把误差变成「一眼能看出 + 一次能改对」比继续堆正则更有价值。
2. **能力空白正好可以补上**：README 里「AI 内容优化、ATS 评分」一直列在未实现，
   而本机 `qwen3-8b` 已经跑通改写。下一步可以做「按目标 JD 打分 + 逐条建议」，
   用现有 `server/routes/aiRewrite.ts` 的模式扩展即可。
3. **简历数据只有导出、没有备份策略**：IndexedDB 清缓存即丢。虽然有 JSON 备份/恢复，
   但没有提醒、没有自动导出、没有"最近一次备份时间"。
4. **模板与排版**：三套模板（classic/compact/accent）+ 一页模式已经够用，
   下一步的性价比在「导出前体检」（已有 `checks.ts`）而不是继续加模板。

## 五、工程

1. **CI 没有 Windows 矩阵**。这次两个 bug（`spawnSync npx.cmd EINVAL`、`node .bin/tsx` 启动失败）
   都只在 Windows + Node 24 上暴露，而 CI 大概率只跑 Ubuntu。建议加 `windows-latest` 到矩阵。
2. **Playwright 浏览器依赖外网 CDN**，国内会卡在 0%（这次就是）。建议：CI 用
   `playwright install chromium` 并缓存；本机文档里补充 `CHROME_PATH` 走系统 Edge/Chrome 的用法。
3. **`.bin/*` 这类跨平台陷阱**：凡是 `spawn` 命令行工具的地方，统一用
   `process.execPath + node_modules/<pkg>/dist/cli.*` 或 `shell: true`（Windows）。
